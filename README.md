# Sequence analysis and Deep Learning Modelling of the MPXV A29 Protein

Data, code and analysis outputs supporting the article "Sequence analysis and Deep Learning Modelling of the MPXV A29" by Dmitrij Gritsok, Sérgio F. Sousa, Martin Hedstrom, Maria C.B.S.M. Montenegro, Célia Gomes Amorim.

A29 (A29L, OPG154) is a ~110 aa membrane protein of the monkeypox virus mature
virion, the orthologue of vaccinia virus A27. This repository contains the
complete analysis: identification of A29 orthologues across *Poxviridae*, their
phylogeny and site-specific evolutionary rates, the sequence-derived secondary
architecture, and co-folding prediction of the trimer with validation against the
vaccinia A27 crystal structure.

**Residue numbering** is identical in VACV A27 and MPXV A29 and is used
throughout. The reference sequence is MPXV A29 YFT67316.1 (= UniProt Q77HM6),
110 aa.

## Repository layout

Each folder is one stage of the analysis and carries its own README with the
tools, parameters, outputs and limitations of that stage.

| Folder | Stage | Article section |
| --- | --- | --- |
| `1_orthologs_msa/` | Ortholog discovery, curation, redundancy reduction, alignment, conservation | 2.1 |
| `2_phylogeny/` | Maximum-likelihood gene tree, branch support, genus monophyly tests; `saturation/` holds the substitution-saturation diagnostic | 2.1 |
| `3_r4s/` | Site-specific evolutionary rates at two taxonomic levels, matrix robustness, cross-level comparison | 2.1 |
| `4_remote_homology/` | HHblits and HHpred searches for homologues beyond *Poxviridae* | 2.1 |
| `5_mpxv_survey/` | Survey of A29 sequence variation across sequenced monkeypox genomes | 2.1 |
| `6_secondary_architecture/` | Signal peptide and topology, secondary structure and disorder, coiled-coil prediction, helical properties | 2.2 |
| `7_structure_prediction/` | Co-folding predictions, restraint screen, validation controls, reported ensemble, structural analysis | 2.3 |

Stages run in order: each reads the outputs of the ones before it. The alignment
produced in `1_orthologs_msa/output_phase7/` and the tree produced in
`2_phylogeny/output_iqtree/` are the two files most of the later stages depend
on.

## Reproducibility

The stages fall into three categories, and the distinction matters when reading
the deposit.

**Reproducible by execution.** The ortholog pipeline, the phylogeny, the
saturation test, the evolutionary-rate analysis and the structural analysis
scripts can all be re-run from the deposited inputs. Where a result is quoted in
the article, the script and its inputs are here.

**Reproducible by inspection.** The web services — the secondary-architecture
predictors, the remote-homology searches, AlphaFold, MolProbity, PDBePISA — cannot
be re-run to the same output, because their underlying databases and models
change. For these the deposit holds the query, the parameters, the access date
and the result as downloaded. A reader can verify that the output says what is
claimed, but not regenerate it.

**Human judgement, recorded not reproduced.** Taxonomic curation
(`1_orthologs_msa/output_phase5/taxonomy_overrides.csv`,
`manual_exclusions.py`), the manual removal of unrelated sequences from the MPXV
survey, and figures drawn by hand in Excel or Inkscape. Each decision is
documented with its reason; none can be regenerated by running anything.

A few figures were drawn manually from deposited data rather than by script —
Fig. S8 (`2_phylogeny/saturation/plot_saturation.xlsx`) and the RMSF plot
(`7_structure_prediction/analysis/4_ensemble_a29_analysis/RMSF_plot.xlsx`). In
both cases the source table is deposited and the spreadsheet carries the chart
definitions.

## Environments

```bash
conda env create -f environment.yml          # main analysis
conda env create -f environment-openmm.yml   # energy minimisation only
```

`environment.yml` covers stages 1, 2, 3 and the analysis scripts of stage 7.
Rate4Site, Socket and InterProScan are not available from conda and are obtained
separately; the file lists where. Boltz-2 ran on Kaggle Notebooks in a
session-local environment built by the notebooks themselves.

Several scripts — the occupancy and conservation summary, the cross-level rate
comparison — use only the Python standard library and run without any
environment.
