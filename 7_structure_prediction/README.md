# Step 7 — Structure prediction of MPXV A29

This folder contains the co-folding predictions of the MPXV A29 trimer and the
controls that support them: an unrestrained benchmark across three predictors, a
screen of distance restraints derived from the vaccinia A27 structure, two
validation controls, a template-guided screen, the ensemble reported in the
article, and the downstream structural analysis.

All predictions model **three identical chains (A, B, C)**. Unless stated
otherwise the input is full-length MPXV A29 (YFT67316.1 = Q77HM6, 110 aa) or
full-length VACV A27 (P11258, 110 aa); the third target is the **3VOP
construct**, the 64-residue ordered region resolved in the vaccinia A27 crystal
structure (residues 21–84, C71A/C72A), modelled as three chains.

**Residue numbering.** Positions are identical in VACV A27 and MPXV A29, and all
residues in this folder — restraints, domain boundaries, analysis ranges — are
quoted in that shared numbering. The 3VOP construct is renumbered from 21 so that
it matches; the deposited mmCIF starts at 1, and the +20 offset is applied when
the contacts are derived. The 3VOP construct is used as a *sequence* in sections
1 to 4; the crystal structure is supplied as a template only in section 5.

Every Boltz-2 run keeps the layout the program writes
(`results_<target>_<tag>_seed<N>/boltz_results_<tag>/…`), with the models and
confidence files in `predictions/`, the MSA in `msa/`, and the processed inputs,
including the compiled restraints, in `processed/`. These names are generated by
Boltz-2 and were not changed, so that the outputs remain consistent with the
files that reference them.

**Where to look first inside a run.** `predictions/<tag>/<tag>_model_0.cif` is
the top-ranked model and `confidence_<tag>_model_0.json` holds its pTM, ipTM and
composite confidence score. The remaining four models of that seed are
`_model_1` to `_model_4`, ranked by the same score.

## The two notebooks

Both run Boltz-2 v2.2.1 on **Kaggle Notebooks** (NVIDIA T4, Python 3.12
environment built with `uv`), install the package in the session, write the YAML
input, run every requested seed, and then classify the resulting topology and
check the imposed restraints. Section 8 of each notebook prints a parameters
record — version, GPU, target, stoichiometry, restraints, sampling settings and
date — which is the provenance record for the run.

| Notebook | Produces |
| --- | --- |
| `run_boltz2_kaggle.ipynb` | all Boltz-2 runs in `1_unrestrained/`, `2_restraints_screening/`, `3_validation/` and `4_reported_model/` |
| `run_boltz2_kaggle_template.ipynb` | all runs in `5_template_guided/`; identical to the above with an additional template block (section 4b) |

To reproduce a run, edit the marked `# ---- EDIT ----` blocks: `PRESET` selects
the target sequence (`Q77HM6`, `P0DTN3`, `P11258` or `3VOP`, each with its own
first-residue offset), `SET_NAME` and `DROP` select the restraint set and any
ablation, and `SEEDS` lists the seeds. In the template notebook, `TEMPLATE`,
`TEMPLATE_THRESHOLD` and `TEMPLATE_FORCE` control the template block; the 3VOP
assembly is fetched from RCSB if not already present.

Sampling settings are the same in every run reported here: 5 diffusion samples
(hence five models per seed), 3 recycling steps, 200 sampling steps, step scale
1.5, the Boltz MSA server, and the inference-time potentials enabled
(`--use_potentials`). Note that `--use_potentials` is Boltz-2's inference-time
steering and is independent of the per-restraint `force` flag, which was `false`
in every run. Chains are declared as **separate entities** of identical sequence,
which is required for chain-specific restraints.

`RUN_TAG` encodes the configuration and appears in every output path: the
restraint set, then `-d<N>` if one restraint was dropped, then `-f` or `-F` for
`force: false` or `true`. Template runs add `-tpl`, and `-t<X>` for a deviation
threshold.

## 1. Unrestrained benchmark (`1_unrestrained/`)

Three targets, three predictors, **90 models per target, 270 in total**:

| Predictor | Version / service | Sampling | Models per target |
| --- | --- | --- | --- |
| AlphaFold3 | AlphaFold Server | 5 independent jobs (`fold_*_run_1…5`), server-assigned seeds recorded in each `*_job_request.json` | 25 |
| AlphaFold2-multimer | ColabFold v1.6.2 | seeds 0–7 in one run | 40 |
| Boltz-2 | v2.2.1 | seeds 1–5, five models per seed | 25 |

Each run folder holds the models and the predictor's own confidence output
(AF3: `summary_confidences_*.json`, `full_data_*.json`; ColabFold:
`scores_rank_*.json`, PAE and pLDDT plots; Boltz-2: `confidence_*.json`,
`pae/pde/plddt_*.npz`). MSAs generated by each service are included; the
BLAST-style database files that `makeblastdb` writes are not.

**Chai-1 was also run and excluded**; see
[`1_unrestrained/excluded_chai1/README.md`](1_unrestrained/excluded_chai1/README.md)
for the runs, the coordinate comparison and the reason.

## 2. Restraint screen (`2_restraints_screening/`)

Ten Boltz-2 runs on full-length MPXV A29, **seed 1 only, five models each**:
restraint sets **S1–S8**, plus two ablations of S1 (`S1-d0`, `S1-d1`) in which
one of its two restraints is removed.

The restrained residue pairs are contacts observed in the vaccinia A27 assembly
(`3vop-assembly1.cif`, measurements in `3vop_distances.pse`), which contains one
parallel (A–B) and two antiparallel (A–C, B–C) interfaces. Non-polymer components
and zero-occupancy residues were removed and the +20 numbering offset applied
before contacts were measured in PyMOL at a Cβ–Cβ cutoff of 8.0 Å, with Cα
substituted for glycine. The biological assembly was verified from the mmCIF
metadata and independently with PDBePISA v1.52 (web server, accessed 11 September
2026). The measured distances are listed in `restraints_sets.txt` and in
Table S14.

**The measured distances were used only to choose which pairs to restrain.** In
every run the restraint applied was a Boltz-2 `contact` constraint with
`max_distance: 8.0` and `force: false`, i.e. a uniform soft upper bound. The YAML
file of each run records exactly what was imposed.

| Set | Restrained pairs |
| --- | --- |
| S1 | A47–C65, A65–C47 |
| S2 | S1 + B47–C65, B65–C47 |
| S3 | S1 + A47–B47, A65–B65 |
| S4 | S2 + A47–B47, A65–B65 |
| S5 | A47–C65, B47–C65 |
| S6 | A65–C47, B65–C47 |
| S7 | S2 + A54–C57, B51–C62 |
| S8 | A54–C57, A57–C54, B51–C62, B62–C51 |
| S1-d0 | S1 without A47–C65 |
| S1-d1 | S1 without A65–C47 |

The sets vary which interfaces are restrained (antiparallel only, antiparallel
plus parallel, one direction only) and which contact region is used (47/65 or
54/57 and 51/62), so the screen tests which contacts are needed rather than
merely how many.

## 3. Validation controls (`3_validation/`)

The S1 restraints were applied unchanged to two sequences whose arrangement is
known experimentally, to test whether the restraints recover that arrangement
rather than imposing an arbitrary one. Both at **seeds 6–10, five models each
(25 models per control)**, chosen not to overlap the reported ensemble.

- `VACV_A27_S1-f/` — full-length VACV A27.
- `3VOP_S1-f/` — the 3VOP construct.

---

## 4. Reported ensemble (`4_reported_model/`)

Full-length MPXV A29 with restraint set S1, **seeds 1–20, five models per seed:
100 models**. `MPXV_A29_S1-f.yaml` is the input used for every seed.

Models were accepted for ensemble analysis if they adopted the
two-parallel/one-antiparallel arrangement and reached ipTM ≥ 0.60; **97 of 100
were accepted**. **The reported model is seed 2, model 0** (`A29_s2m0` in the
analysis folder), selected by `analysis/4_ensemble_a29_analysis/analyse_ensemble.py`;
it is the structure used for the Socket2, solvent-accessibility, MolProbity and
3VOP-comparison analyses.

---

## 5. Template-guided screen (`5_template_guided/`)

The 3VOP biological assembly supplied through the `templates:` block, to test
whether structural information by itself recovers the topology that the contact
restraints impose. Five configurations, a two-by-two of deviation threshold
against the steering potential, plus one combined run:

| Tag | Restraints | Template threshold | `force` | Seeds | Models |
| --- | --- | --- | --- | --- | --- |
| `none-f-tpl` | — | unset | false | 1 | 5 |
| `none-f-tpl-F` | — | unset | true | 1 | 5 |
| `none-f-tpl-t2.0` | — | 2.0 Å | false | 1 | 5 |
| `none-f-tpl-t2.0-F` | — | 2.0 Å | true | 1 | 5 |
| `S1-f-tpl-t2.0` | S1 | 2.0 Å | false | 1–5 | 25 |

Restraints and templates were not combined in any other run, so that the
contribution of each can be attributed separately. These runs are a screen, not a
reported result; the reported ensemble (section 4) uses no template.

**Dependencies.** `analyse_ensemble.py` requires numpy and gemmi;
`ensemble_sasa.py` requires numpy, gemmi and Biopython; `compare_chai1_coordinates.py`
requires numpy and Biopython. All were run in the `r4s` conda environment
(numpy 2.5.3, gemmi 0.7.5, Biopython 1.88). `minimise.py` needs its own
environment (OpenMM 8.6.1, PDBFixer 1.12). The arm-specific settings of
`analyse_ensemble.py` — residue numbering, restraint set, distance bound,
helix-fit range — are command-line options, with examples in the script's
docstring.

**Helix-axis fitting ranges.** Three appear in this folder and are not
interchangeable: `analyse_ensemble.py` and `ensemble_sasa.py` fit residues
44–100, the notebooks' in-session topology check uses 44–84, and the PyMOL
session log uses 47–65. The 44–100 range is the one the reported classification
and RMSF rest on.
